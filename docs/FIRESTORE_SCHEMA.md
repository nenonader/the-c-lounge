# The C Lounge — Firestore Schema (v72)

**Made By Eng Nayer Nader**

Every collection, every field, and the queries each one is designed to answer.

## Conventions

- **IDs are labels, never keys.** Every value encoded in a document ID is *also*
  stored as a real field on that document. Nothing in the application parses an
  ID to recover data.
- **All IDs are chronologically sortable.** The UTC stamp comes first, so lexical
  order in the console is time order.
- **`expiresAt`** drives Firestore TTL deletion. The field is written by the
  application; the TTL *policy* is a console setting you must enable per
  collection (Firestore → Time-to-live).
- **`ipHash`** is an HMAC-SHA256 of the IP under `LOG_HASH_SALT`, truncated to 24
  characters. Use it for correlation. `ipAddress` is stored separately and is the
  field to drop first if you tighten your privacy posture.

## `conversations/{conv_...}`

One chat session. ID: `conv_<stamp>_<country>_<device>_<rand>`
e.g. `conv_2026-09-06T10-29-55Z_eg_mobile_a3f9c1`

| Field | Type | Notes |
| --- | --- | --- |
| `schemaVersion` | number | `2` for v72 documents |
| `status` | string | `active` \| `handoff_ready` |
| `service` | string \| null | The discipline, once identified |
| `handoffReady` | bool | A brief was prepared for the desk |
| `messageCount` | number | Total messages; also the sequence source |
| `visitorTurns` / `conciergeTurns` | number | Split of the above |
| `claudeTurns` | number | **Turns actually generated by Claude** |
| `fallbackTurns` | number | **Turns served by the holding reply** |
| `blockedTurns` | number | Turns refused by the injection gate |
| `lastServedBy` | string | `claude` \| `fallback` \| `policy` \| `unreachable` |
| `lastModel` | string \| null | Which model answered most recently |
| `deviceType` | string | `mobile` \| `tablet` \| `desktop` \| `unknown` |
| `country` | string | Two-letter code from the proxy header, or `XX` |
| `language` | string \| null | First `Accept-Language` entry |
| `entryReferrer` | string \| null | Where the visitor arrived from |
| `visitorId` / `analyticsSessionId` | string \| null | Joins to the analytics stream |
| `ipHash` / `ipAddress` / `userAgent` | string | Request provenance |
| `firstMessageAt` / `lastMessageAt` | timestamp | Conversation span |
| `createdAt` / `updatedAt` / `expiresAt` | timestamp | 30-day default retention |

**Answers:** *Which conversations went degraded?* → `fallbackTurns > 0`.
*Which reached the desk?* → `handoffReady == true`, ordered by `createdAt`.

## `conversations/{conv_...}/messages/{msg_...}`

One message. ID: `msg_<6-digit sequence>_<role>` e.g. `msg_000002_assistant`

The zero-padded sequence comes **first** so the console lists a transcript in the
order it was spoken. With auto-IDs every transcript appeared shuffled.

| Field | Type | Notes |
| --- | --- | --- |
| `sequence` | number | 1-based, allocated in a transaction |
| `role` | string | `user` \| `assistant` |
| `content` | string | Truncated at 4,000 characters |
| `characters` | number | Original length before truncation |
| `createdAt` / `expiresAt` | timestamp | |

Writes go through a Firestore transaction so `messageCount` on the parent and
`sequence` here can never diverge under concurrent turns.

## `chat_turns/{turn_...}` — new in v72

One record per concierge turn. ID: `turn_<stamp>_<servedBy>_<rand>`

**This is the collection that would have made the v71 outage visible in minutes
rather than days.**

| Field | Type | Notes |
| --- | --- | --- |
| `conversationId` | string | The `conv_...` document ID |
| `servedBy` | string | `claude` \| `fallback` \| `policy` \| `unreachable` |
| `degraded` | bool | `servedBy != "claude"` — the field to alert on |
| `model` | string \| null | Which model answered |
| `intent` | string \| null | `question` \| `request` \| `comparing` \| `small_talk` \| `confirming` \| `declining` \| `probing` \| `sensitive` |
| `service` | string \| null | Discipline the model identified |
| `failure` | string \| null | Why it fell back, when it did |
| `injectionScore` | number \| null | 0 is clean; ≥3 is blocked |
| `aiLatencyMs` | number \| null | End-to-end turn time in the AI service |
| `replyCharacters` | number | Length of what the visitor saw |
| `handoffReady` / `reference` / `deskId` | | Set when a brief was prepared |
| `country` / `deviceType` / `visitorId` / `analyticsSessionId` / `ipHash` | | Context |
| `createdAt` / `expiresAt` | timestamp | 90-day retention |

**Answers:** *Is the bot actually thinking?* → count `servedBy == "claude"`
against the total. *Why did it stop?* → group by `failure`.

## `security_events/{sec_...}` — new in v72

Blocked and flagged prompt-injection attempts.
ID: `sec_<stamp>_<kind>_<rand>`

| Field | Type | Notes |
| --- | --- | --- |
| `kind` | string | `injection_blocked` \| `injection_flagged` |
| `conversationId` | string | |
| `score` | number | Weighted classifier score |
| `country` / `deviceType` / `ipHash` / `userAgent` | | Attribution |
| `createdAt` / `expiresAt` | timestamp | 365-day retention |

Note the distinction: `flagged` means the message scored above zero but below the
block threshold — useful for tuning. `blocked` means the turn was refused before
a single token was spent on it.

## `inquiries/{inq_...}`

Form submissions. ID: `inq_<stamp>_<REFERENCE>_<request-type>`
e.g. `inq_2026-09-06T10-31-02Z_CLC-20260906-9F3A2B1C_private-aviation`

The public reference keeps its **original case** so the desk can paste a
reference a member quoted on the phone straight into the console search bar.

---

## `analytics_events/{evt_...}`

ID: `evt_<stamp>_<event-type>_<rand>` e.g. `evt_2026-09-06T10-29-55Z_scroll-depth_31cd50`

Existing fields are unchanged (`eventType`, `eventVersion`, `visitorId`,
`sessionId`, `pagePath`, `data`, `country`, `deviceType`, `ipHash`, `createdAt`,
`expiresAt`). Only the document ID changed — the event type is now visible in the
console listing without opening anything.

---

## `analytics_sessions/{asess_...}` · `visitor_sessions/{vsess_...}`

IDs: `asess_<stamp>_<country>_<device>_<rand>`, `vsess_<stamp>_<country>_<device>_<rand>`

Fields unchanged. As above, only the IDs are now self-describing — you can see at
a glance that a row is a mobile session from Egypt without clicking into it.

---

## `audit_events/{audit_...}` · `routing_logs/{route_...}`

IDs: `audit_<stamp>_<type>_<rand>`, `route_<stamp>_<desk>_<source>_<rand>`

`audit_events` retention is extended to 365 days in v72 — a handoff record is a
business record, not telemetry, and 30 days was too short to answer a question
about last quarter.

## Composite indexes

Twelve are declared in `firebase/firestore.indexes.json`. The ones you will use
most:

| Query | Index |
| --- | --- |
| Degraded turns, newest first | `chat_turns`: `degraded` ASC, `createdAt` DESC |
| Volume by path over time | `chat_turns`: `servedBy` ASC, `createdAt` DESC |
| Failure triage | `chat_turns`: `failure` ASC, `createdAt` DESC |
| One conversation's turns in order | `chat_turns`: `conversationId` ASC, `createdAt` ASC |
| Conversations that reached the desk | `conversations`: `handoffReady` ASC, `createdAt` DESC |
| Conversations by discipline / market | `conversations`: `service` \| `country` ASC, `createdAt` DESC |
| Injection attempts by kind | `security_events`: `kind` ASC, `createdAt` DESC |

Deploy with:

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

## Security rules

Server-only, with no exceptions. Every collection is named and denied explicitly,
followed by a catch-all deny. The Admin SDK bypasses rules entirely, and no
browser or mobile client holds a Firebase credential for this project.

This is deliberately **not** "deny by default with a few holes" — there are no
holes. If a future feature needs client reads, add one narrowly scoped `match`
block and write a test for it. Do not loosen the catch-all.
